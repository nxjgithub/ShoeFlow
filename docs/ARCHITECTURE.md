# 架构说明

## 总体链路

项目按 8 类核心对象组织：

1. `VideoSample`：爆款视频样本
2. `VideoAnalysis`：视频结构化解析结果
3. `ContentTemplate`：可复用内容模板
4. `Product`：女鞋商品标准化对象
5. `TemplateMatch`：模板与商品适配结果
6. `ScriptOutput`：脚本、镜头与素材清单
7. `ProductionRecord`：成片生产记录
8. `PerformanceRecord`：发布与投放回流数据

当前代码先实现前 6 类对象的最小骨架，并为回流数据预留 fixture。

## 模块职责

### 样本层

负责记录视频从哪里来、为什么值得解析、它对应什么平台和业务上下文。

关键输入：

- 平台
- 视频 URL 或本地文件
- 标题/正文/标签
- 点赞、收藏、评论、转发等互动指标
- 是否带商品、是否女鞋强相关

关键输出：

- 可进入解析流程的样本对象

### 解析层

负责把原始视频转成结构化对象。短期可以先人工标注或半自动生成，长期再接入抽帧、镜头切片、OCR、语音转写、视觉标签和片段角色识别。

### 模板层

负责从解析结果中提炼可复用逻辑。模板不是复制文案，而是记录钩子类型、卖点顺序、镜头结构、情绪节奏、文案风格和商品变量位。

### 商品层

负责把自家女鞋 SKU 转成内容生产可以理解的对象。重点字段包括鞋型、鞋头、跟高、材质、主卖点、次卖点、目标人群、使用场景和风险点。

### 适配层

负责判断某个模板是否适合某个商品。输出不只是一个分数，还要包含适配原因、不适配原因、需要替换的商品变量和高风险镜头。

### 生成层

负责输出脚本、镜头清单和素材清单。当前阶段生成结果用于人工剪辑，不直接承诺自动成片。

### 回流层

负责把发布效果映射回模板和商品。每条成片必须能追溯到样本来源、模板版本、商品版本、脚本版本、发布平台和表现指标。

## 当前实现策略

当前代码只提供轻量骨架：

- 使用 JSON fixture 表达业务对象
- 使用标准库完成读写和校验
- 使用 CLI 跑通最小演示链路
- 保留后续替换真实视频处理与 AI 生成模块的位置

这能保证早期不会被工具链复杂度拖住，同时让业务对象先稳定下来。
